# School Microsoft feasibility gate

Status: **not verified against a school tenant**. No Microsoft account, app registration, tenant consent or test DriveItem IDs were provided. Graph is disabled until all four server-side settings and the encryption key are configured. Manual upload is the fallback for a verified Supabase user with completed business setup; the former shared demo login has been removed. No background/delta polling is implemented.

1. Sign into [Microsoft 365](https://www.microsoft365.com/) with the intended school account. Verify OneDrive exists and an .xlsx can be edited and saved in Excel Online. Record the approved test user (no passwords in this document).
2. In [Microsoft Entra](https://entra.microsoft.com/), verify students may register an app, or ask the tenant administrator to register a single-tenant Web app. Record tenant ID, client ID and approved redirect URI. Outlook access alone does not establish Graph permissions. [Microsoft tenant app-registration guidance](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/delegate-app-roles).
3. Request delegated `Files.Read` plus `offline_access` for refresh. Do not request tenant-wide application file access. The download endpoint's least privileged delegated scope is Files.Read: [DriveItem download reference](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content). Tenant administrators may still require approval.
4. Register the exact backend callback URL. For local Vite proxy use `http://localhost:3000/api/v1/auth/microsoft/callback`; for direct API use `http://localhost:8000/api/v1/auth/microsoft/callback`. Production should use one HTTPS origin for frontend/API so state cookies work reliably. Set `MICROSOFT_*` and a generated Fernet `TOKEN_ENCRYPTION_KEY` only on the backend. Keep the encryption key stable across deploys; rotation requires reconnecting saved sessions.
5. From Data Source, connect Microsoft, choose a test .xlsx, record drive/item IDs shown by the status API, click Sync Now, then click again to verify `up_to_date`. Verify consent denial, expired authorization and throttling produce an explicit message while previous records remain usable.
6. Edit/save locally in the OneDrive folder. Verify BizFlow stays unchanged before OneDrive uploads. Wait for cloud save, then Sync Now and confirm exactly one updated row. A file in an unsynced local folder requires re-upload.
7. Record tenant restrictions, consent approver/date, redirect URI and test outcome in the release handoff. If authorization is not working by the team's Day 2 checkpoint, leave Graph disabled for release and demonstrate the manual path.

Implementation uses server-side authorization code exchange, PKCE S256, one-use expiring state, browser state cookie, encrypted saved tokens, refresh and link ownership. [OAuth protocol reference](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow). Download redirects are followed without copying the bearer token onto the signed download URL; the download is size bounded. Cloud version is checked before and after download to catch saves in progress. Unlink removes saved tokens; revoke the grant separately in Microsoft account permissions if required. A tenant test is still required before enabling this in a public release.
